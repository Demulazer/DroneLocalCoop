# Дополнение: разворот корпуса по левому стику

Эта инструкция применяется ПОСЛЕ первой инструкции переноса аркадного движения.
Откатывать уже перенесённые изменения не нужно. Файлы брать из текущей папки
проекта на компьютере, где работает Codex: они содержат исправленный вариант.

## Что изменилось

Раньше корпус сохранял направление, а транспорт перемещался боком.
Теперь стик выбирает направление относительно внешней камеры, движение начинается
сразу, а корпус быстро доворачивается к нему. Диагонали поддерживаются.
Стик вниз тоже задаёт новое направление и разворот на него, а не автомобильный
задний ход с прежним направлением корпуса.

Внешняя камера следует за позицией, но перестаёт вращаться вместе с корпусом.
Её Spring Arm получает абсолютное вращение автоматически в игре. Направление
ввода берётся от самого длинного Spring Arm. При переключении на камеру салона
сохраняется ориентир внешней камеры. Ручное вращение внешней камеры меняет ориентир.
При отсутствии Spring Arm ориентир фиксируется по начальному направлению камеры.

Это наземное аркадное движение с сохранённой подвеской и гравитацией, не свободный полёт.

## 1. Закрыть редактор

На втором компьютере закрой Unreal Editor и Visual Studio. Сохрани резервную копию
или коммит перед заменой. Корень проекта — папка с DronesSetup.uproject.

## 2. Повторно заменить файлы C++

Все перечисленные файлы находятся в Source/DronesSetup/.
Копируй целиком с заменой, не добавляй куски вручную.

| Файл | Действие |
|---|---|
| ArcadeCoastingComponent.h | Заменить ещё раз |
| ArcadeCoastingComponent.cpp | Заменить ещё раз |
| ArcadeDrivingSettings.h | Заменить ещё раз |
| LocalMultiplayerSubsystem.h | Заменить ещё раз |
| LocalMultiplayerSubsystem.cpp | Заменить ещё раз |
| LocalMultiplayerViewportClient.h | Заменить: добавлена совместимость ввода с UE 5.5 |
| LocalMultiplayerViewportClient.cpp | Заменить: добавлена совместимость ввода с UE 5.5 |

ArcadeDriveMath.h нужен самому движению; без него проект не соберётся.

## 3. Перенести вспомогательные файлы

- Scripts/Test-SplitScreen.ps1 — заменить актуальной версией.
- Scripts/Tests/ArcadeDriveMathTests.cpp — новый файл; создать папку Tests, если её нет.
- INPUT_GUIDE.md — заменить актуальной инструкцией.

Последние три файла не нужны игре для работы; это проверка математики и документация.

## 4. Добавить две настройки

В Config/DefaultGame.ini найди существующую секцию ArcadeDrivingSettings.
Добавь TurnResponse и MaxTurnSpeed. Полная секция теперь выглядит так:

```ini
[/Script/DronesSetup.ArcadeDrivingSettings]
MaxSpeed=1800.0
MovementResponse=12.0
TurnResponse=14.0
MaxTurnSpeed=720.0
AirControl=0.35
bEnableArcadeCoasting=True
CoastDecayRate=10.0
StopSpeed=5.0
```

Не создавай второй экземпляр секции. Остальные секции не меняй.
TurnResponse — отзывчивость разворота; MaxTurnSpeed — предел в градусах в секунду.
720 означает предел 2 оборота в секунду, а не непрерывное вращение: при достижении
заданного направления угловая скорость стремится к нулю.

## 5. Пересобрать

1. Редактор должен быть закрыт. Не ограничивайся Live Coding.
2. ПКМ по DronesSetup.uproject → Generate Visual Studio project files.
3. Открой DronesSetup.sln.
4. Выбери Development Editor / Win64.
5. Build проекта DronesSetup; дождись успешного завершения.
6. Открой проект в используемой на втором компьютере версии движка.

Менять EngineAssociation и понижать версию проекта не требуется.
Binaries, Intermediate, Saved и DerivedDataCache с первого компьютера не переносить.

## 6. Что менять внутри Unreal

После сборки: Edit → Project Settings → Game → Arcade Driving.
Проверь появление Turn Response = 14 и Max Turn Speed = 720.
Если значения уже считались из ini, вручную ничего сохранять не требуется.

IMC_Default, Input Actions и Blueprint оставь в состоянии после первой инструкции.
Не удаляй VehicleAdvPawn, Vehicle Movement, обработчики ручника, камеры или предметов.
Не добавляй вручную ArcadeCoastingComponent. Не меняй родительский класс Pawn.
Не выставляй Absolute Rotation камер вручную — код делает это во время игры.

## 7. Ручная проверка

Запускай Play, не Simulate; Net Mode = Standalone (локальная игра).
Проверь на свободной площадке обоих игроков:

| Действие | Ожидаемый результат |
|---|---|
| Стик строго вправо | Движение вправо относительно внешней камеры + разворот корпуса |
| Удерживать вправо 2–3 секунды | Корпус доворачивается и перестаёт вращаться, машина не кружит |
| Четыре диагонали | Движение и разворот к каждой диагонали |
| Из вправо резко влево | Быстрый разворот и смена направления без автомобильной дуги |
| Стик вниз | Движение от направления камеры назад + разворот корпуса к этому направлению |
| Отпустить стик | Прекращение управляемого поворота и торможение на земле |
| Сменить камеру | Ориентир управления остаётся внешней камерой |
| Повернуть внешнюю камеру вручную | Направление ввода меняется вместе с ней |
| Reset/замена машины | Компонент присутствует, управление сохраняется |
| Два геймпада | Каждый управляет своей машиной |

Отдельно проверь склоны, прыжок, стены, подбор и бросок. Старый HUD скорости может
отображать продольную составляющую, а не полную горизонтальную скорость.

## 8. Автоматические проверки

После сборки открой PowerShell в корне проекта:

```powershell
.\Scripts\Test-SplitScreen.ps1 -EngineRoot 'C:\Program Files\Epic Games\UE_5.6'
```

Подставь реальный путь к своему движку. Скрипт запускает две тестовые карты и
проверяет также совпадение направления корпуса с вводом и неподвижность ориентира камеры.
Ожидаются VehicleExampleMap : PASS и VehicleOffroadExampleMap : PASS.
Логи: Saved/Logs/VehicleExampleMap-SplitScreen.log и VehicleOffroadExampleMap-SplitScreen.log.
Сообщение об отсутствии свежего лога означает, что тест не запустился, а не прошёл.

Для математических тестов в открытом редакторе можно выполнить в консоли:

```text
Automation RunTests Drones.Arcade
```

Они проверяют только расчёты направления и поворота, не столкновения и камеры.

## Результат проверки на первом компьютере

- Сборка редакторных модулей на установленном UE 5.5: успешно.
- Отдельный C++-тест именно того заголовка, который использует движение: 11509 проверок PASS.
  Восемь направлений, пять направлений камеры, сила отклонения, переход ±180 градусов,
  разворот на 180 градусов, ограничение угловой скорости, удержание ввода, 30/60/120 FPS.
- Запуск тестов внутри Unreal и на игровых картах: НЕ подтверждён. UnrealEditor-Cmd
  завершился без создания журнала тестов, UnrealEditor также не запустил тесты.
  Поэтому физика, взаимодействие с Blueprint и камерой требуют проверки в Play.
- На UE 5.6 сборка и запуск здесь не проверены: эта версия движка не установлена.
