# Перенос DronesSetup с UE 5.5.4 на UE 5.6

Сплит-скрин, геймпады, подбор предметов, прицеливание, бросок и физический толчок.

Актуализировано: 5 ноября 2026 года.

Документ предназначен программисту, объединяющему проекты. Он заменяет прежнюю инструкцию по переносу сплит-скрина: все необходимые шаги и дополнения собраны здесь. В примерах `MyGame` — имя существующего целевого проекта; замените его настоящим именем. Имя переносимого Runtime-модуля `DronesSetup` для первого переноса сохраняется.

## 1. Состояние проекта и выбор способа переноса

Исходный проект создан на UE 5.5.4 и содержит C++-модуль, Blueprint-ресурсы и дополнительный Editor-модуль. На компьютере подготовки установлен UE 5.5; сборка, запуск и физическое поведение на UE 5.6 пока не проверены.

В исходном проекте выполнены автоматические проверки двух локальных игроков, маршрутизации ввода, движения стиком и быстрого замедления. В игровом мире Unreal/Chaos проверены подбор, независимое владение предметами, перенос, прицеливание, диагональный бросок, инерция и усиленный толчок для SportsCar и OffroadCar. Новые механики не проходили отдельный визуальный прогон на физических Xbox/PS-геймпадах. Синтетические проверки не заменяют такую проверку после объединения.

Выберите один из вариантов:

| Вариант | Когда использовать | Что сохраняется автоматически |
|---|---|---|
| А. Обновить копию всего DronesSetup до UE 5.6 | Удобнее использовать настроенный проект как основу и затем добавить в него содержимое другого проекта | Имена модулей, пути ресурсов, Blueprint-связи, настройки и карты |
| Б. Перенести в существующий проект UE 5.6 | В целевом проекте уже есть важные настройки, код, уровни или игровые системы | Только выбранные ресурсы и их зависимости; исходники, Config и конфликты систем объединяются отдельно |

Перед любым вариантом:

1. Сохраните все ассеты и закройте редакторы перед изменением исходников и Config.
2. Сделайте копию/коммит исходного проекта UE 5.5.4 и отдельную копию/коммит целевого проекта.
3. Зафиксируйте, какие автомобили, GameMode, PlayerController, GameViewportClient и Input Mapping Context уже используются в целевом проекте.
4. Определите, есть ли в нём собственные ресурсы по путям `/Game/VehicleTemplate/...`. Их нельзя автоматически заменить или пропустить без проверки связей.
5. Сохраните исходную версию UE 5.5.4 отдельно. Ассеты, пересохранённые в UE 5.6, не используйте как обратную замену для неё.

## 2. Вариант А: обновление копии всего текущего проекта

1. Запустите UE 5.6, выберите `DronesSetup.uproject` и **Open a Copy**. Работайте с полученной копией.
2. Пересоберите C++ под UE 5.6: DLL, собранные для 5.5.4, не подходят.
3. Если автоматическая сборка не прошла, сгенерируйте Visual Studio project files для копии и соберите Target **DronesSetupEditor**, конфигурация **Development Editor**, платформа **Win64**.
4. Для первого совместимого запуска можно оставить существующий `IncludeOrderVersion.Unreal5_5`. Переход на `Unreal5_6` и исправления порядка include выполняйте отдельно по результатам сборки. Наличие совместимого enum не гарантирует совместимость всех API.
5. Учтите, что теперь в проекте два модуля:
   - `DronesSetup` — Runtime, нужен для сплит-скрина, маршрутизации ввода, модификатора стика и замедления;
   - `DronesSetupEditor` — Editor, содержит инструменты создания и проверки Blueprint. Он включён в текущие `.uproject` и Editor Target и также потребует сборки под 5.6.
6. Editor-модуль не нужен для исполнения уже сохранённых механик. Если решено исключить его из копии, уберите элемент `DronesSetupEditor` из массива `Modules` в `.uproject` и строку `ExtraModuleNames.Add("DronesSetupEditor");` из Editor Target. Runtime-модуль оставьте. Его команды проверки после этого недоступны.
7. Откройте `VehicleExampleMap` и `VehicleOffroadExampleMap`. Скомпилируйте и сохраните задействованные Blueprint, включая базовый автомобиль, оба автомобиля, контроллер и предмет.
8. Выполните проверки из раздела 7 в редакторе, Standalone Game и Development-пакете.

При таком обновлении не заменяйте `IMPLEMENT_PRIMARY_GAME_MODULE` на `IMPLEMENT_MODULE`: DronesSetup остаётся основным модулем этого проекта. Такая замена нужна только для варианта Б, когда он добавляется к другому основному модулю.

Если после обновления в DronesSetup добавляется содержимое другого проекта, проверьте конфликты ресурсов, GameMode, контроллеров, ввода и Config по тем же правилам, что в варианте Б.

[Официальный порядок обновления через Open a Copy](https://dev.epicgames.com/documentation/en-us/unreal-engine/updating-projects-to-newer-versions-of-unreal-engine?application_version=5.6).

## 3. Вариант Б: перенос в существующий проект UE 5.6

### 3.1. Подготовьте целевой проект

Включите плагины:

- **Enhanced Input**;
- **Raw Input**;
- **Chaos Vehicles** — имя в `.uproject`: `ChaosVehiclesPlugin`.

Новые механики используют стандартные компоненты Engine, Enhanced Input и физику Chaos. Отдельный сторонний плагин прицеливания не требуется.

Если целевой проект Blueprint-only, добавьте через редактор пустой C++-класс, чтобы появились основной модуль и Game/Editor Target.cs. Закройте редактор перед копированием исходников и правкой конфигурации.

### 3.2. Перенесите обязательный Runtime-модуль

Скопируйте папку `Source/DronesSetup` целиком в `Source` целевого проекта. В ней должны быть `DronesSetup.Build.cs` и все `.h/.cpp`, включая:

| Файлы | Назначение |
|---|---|
| `DronesSetup.cpp` | Регистрация внутренних клавиш Sony `DS4Raw_*` при запуске модуля |
| `LocalMultiplayerSubsystem.*` | Второй локальный игрок, автомобили, камеры, HUD, установка контекста ввода |
| `LocalMultiplayerViewportClient.*` | Присоединение и маршрутизация геймпадов |
| `StickHalfAxisModifier.*` | Разделение оси стика на газ и тормоз |
| `ArcadeCoastingComponent.*`, `ArcadeDrivingSettings.h` | Быстрое гашение качения автомобиля |

В целевом проекте уже есть основной модуль. В скопированном `Source/DronesSetup/DronesSetup.cpp` замените только последнюю регистрацию:

```cpp
IMPLEMENT_PRIMARY_GAME_MODULE(FDronesSetupModule, DronesSetup, "DronesSetup");
```

на:

```cpp
IMPLEMENT_MODULE(FDronesSetupModule, DronesSetup);
```

Остальной `StartupModule` сохраните: он регистрирует `DS4Raw_*`.

В `.uproject` целевого проекта добавьте в существующий массив `Modules` элемент, сохранив его собственный основной модуль:

```json
{ "Name": "DronesSetup", "Type": "Runtime", "LoadingPhase": "Default" }
```

В конструкторы существующих `MyGame.Target.cs` и `MyGameEditor.Target.cs` добавьте:

```csharp
ExtraModuleNames.Add("DronesSetup");
```

Исходные `DronesSetup.Target.cs` и `DronesSetupEditor.Target.cs` из корня `Source` в другой проект не переносите: используйте targets целевого проекта.

`DronesSetup.Build.cs` переносится целиком. Текущий набор зависимостей:

```csharp
PublicDependencyModuleNames.AddRange(new[] {
    "Core", "CoreUObject", "Engine", "EnhancedInput", "InputCore",
    "ApplicationCore", "UMG", "ChaosVehicles", "DeveloperSettings"
});
```

Сохранение имени `DronesSetup` важно: `IMC_Default` содержит сериализованные ссылки на `/Script/DronesSetup.StickHalfAxisModifier`, а Config — на `LocalMultiplayerViewportClient` и `ArcadeDrivingSettings`. При переименовании потребуются изменения API-макросов, путей `/Script` и Core Redirects. Для первого объединения имя не меняйте.

Сгенерируйте файлы решения и соберите `MyGameEditor` под UE 5.6. `Binaries`, `Intermediate`, `Saved` и `DerivedDataCache` исходного проекта в целевой проект не копируйте.

### 3.3. При необходимости перенесите Editor-модуль

Подбор, прицел, бросок и толчок исполняются в сохранённых Blueprint. Для их работы `DronesSetupEditor` не обязателен.

Если нужны инструменты создания и автоматической проверки:

1. Скопируйте `Source/DronesSetupEditor` целиком, включая Build.cs, командлет и `ThrowAim.cpp`.
2. Добавьте в массив `Modules` целевого `.uproject`:

```json
{ "Name": "DronesSetupEditor", "Type": "Editor", "LoadingPhase": "Default" }
```

3. Добавьте только в конструктор `MyGameEditor.Target.cs`:

```csharp
ExtraModuleNames.Add("DronesSetupEditor");
```

4. Сохраните зависимости Editor Build.cs: `Core`, `CoreUObject`, `Engine`, `UnrealEd`, `BlueprintGraph`, `Kismet`, `KismetCompiler`, `EnhancedInput`, `InputBlueprintNodes`, `InputCore`.
5. Пересоберите Editor Target. При несовместимости инструментов с API UE 5.6 адаптируйте их отдельно; сохранённая игровая логика от этого модуля не зависит.

Не добавляйте Editor-модуль в Game Target или Runtime-зависимости. Если инструменты не переносятся, не добавляйте их регистрацию и строку в Editor Target.

### 3.4. Перенесите ресурсы через Migrate

В исходном UE 5.5.4 выберите актуальную папку `Content/VehicleTemplate` в Content Browser: правая кнопка → **Migrate / Asset Actions → Migrate**. Если для папки меню недоступно, выделите её ресурсы рекурсивно.

Проверьте зависимости в Asset Report и укажите именно папку **Content** целевого проекта. Не исключайте зависимости только потому, что их имена похожи на ресурсы целевого проекта.

Обязательные игровые ресурсы, пути относительно `Content/VehicleTemplate`:

| Ресурс | Что должно сохраниться |
|---|---|
| `Input/IMC_Default` | Актуальные клавиатурные и геймпадные привязки, модификатор оси стика |
| `Input/Actions` | Все действия управления, в том числе `IA_Pickup`, `IA_Throw` |
| `Blueprints/VehicleAdvPawn` | Базовый автомобиль, графы `Pickup and Throw`, `Throw Aiming`, переменные и компоненты прицела |
| `Blueprints/VehiclePlayerController`, `Blueprints/VehicleUI` | Ввод, владение автомобилем, отдельный HUD игрока |
| `Blueprints/VehicleAdvGameMode`, `Blueprints/OffroadGameMode` | Настройки игровых классов |
| `Blueprints/SportsCar/SportsCar_Pawn`, `Blueprints/OffroadCar/OffroadCar_Pawn` | Наследование базы, камеры, физика и управление |
| `Blueprints/BP_ThrowableCube` и его потомки | Подбор, перенос, запуск, физика, граф `Throw Impact Push`, исключения столкновений с бросившей машиной |
| `Materials/M_ThrowAimRed` | Красный светящийся материал линии и точки |
| Меши, материалы, колёса, Physics Assets и прочие зависимости | Полная работа автомобилей и предметов |
| `Maps/VehicleExampleMap`, `Maps/VehicleOffroadExampleMap` | Исходные тестовые уровни |

На `VehicleExampleMap` размещены четыре тестовых куба. На целевом уровне разместите экземпляры `BP_ThrowableCube` отдельно, если исходная карта не используется. Для карт с World Partition/External Actors проверьте наличие акторов после миграции: не ограничивайте ручное копирование одним `.umap`.

**Migrate копирует ассеты, но не объединяет Blueprint-графы и не переносит C++/Config.** При совпадении путей нельзя без анализа выбирать Yes All или No All: перезапись может уничтожить работу целевого проекта, а пропуск — оставить старую базу без новых механик. Сохраните обе версии в резервных копиях, определите итоговый базовый Blueprint и вручную объедините необходимые графы, переменные, компоненты, значения и наследование.

Для первого переноса сохраняйте структуру `/Game/VehicleTemplate/...`. В Runtime-коде жёстко указаны пути к `IMC_Default`, `VehicleUI` и отдельным Input Actions. Если пути изменяются, исправьте соответствующие `LoadObject`/`LoadClass` в `LocalMultiplayerSubsystem.cpp`, проверьте Blueprint-ссылки и пересоберите проект. Одних redirectors редактора для строковых загрузок в упакованной игре недостаточно. Если перенесены Editor-инструменты, исправьте также их пути в обоих `.cpp` и ожидания тестов.

[Официальная процедура Migrate](https://dev.epicgames.com/documentation/en-us/unreal-engine/migrating-assets-in-unreal-engine?application_version=5.6).

### 3.5. Объедините настройки проекта

Не заменяйте Config целевого проекта целиком: сохраняйте его карты, рендеринг, устройства и собственные системы. Объединяйте параметры соответствующих секций без дублирующих противоречивых значений.

В `Config/DefaultEngine.ini`:

```ini
[/Script/EngineSettings.GameMapsSettings]
bUseSplitscreen=True
TwoPlayerSplitscreenLayout=Vertical
bOffsetPlayerGamepadIds=False

[/Script/Engine.Engine]
GameViewportClientClassName=/Script/DronesSetup.LocalMultiplayerViewportClient
```

`Vertical` — игроки слева/справа; `Horizontal` — сверху/снизу. Если у целевого проекта уже есть собственный GameViewportClient, объедините реализации или сделайте его наследником нашего класса. Две независимые настройки viewport-класса одновременно назначить нельзя.

В `Config/DefaultInput.ini`:

```ini
[/Script/Engine.InputSettings]
DefaultPlayerInputClass=/Script/EnhancedInput.EnhancedPlayerInput
DefaultInputComponentClass=/Script/EnhancedInput.EnhancedInputComponent
bFilterInputByPlatformUser=False
```

Из исходного `Config/DefaultInput.ini` перенесите секцию `[/Script/RawInput.RawInputSettings]` с конфигурацией Sony `054C:09CC`. Не потеряйте длинную строку AxisProperties/ButtonProperties. Существующие конфигурации других устройств целевого проекта сохраняйте; одинаковый профиль Sony повторно не добавляйте.

Текущий профиль Sony:

```ini
[/Script/RawInput.RawInputSettings]
+DeviceConfigurations=(VendorID="0x054C",ProductID="0x09CC",AxisProperties=((Key=DS4Raw_Gamepad_RightY,bGamepadStick=True,bInverted=True),(Key=DS4Raw_Gamepad_RightX,bGamepadStick=True),(Key=DS4Raw_Gamepad_LeftY,bGamepadStick=True,bInverted=True),(Key=DS4Raw_Gamepad_LeftX,bGamepadStick=True),(bEnabled=False),(bEnabled=False),(Key=DS4Raw_Gamepad_RightTriggerAxis),(Key=DS4Raw_Gamepad_LeftTriggerAxis),(bEnabled=False)),ButtonProperties=((Key=DS4Raw_Gamepad_FaceButton_Left),(Key=DS4Raw_Gamepad_FaceButton_Bottom),(Key=DS4Raw_Gamepad_FaceButton_Right),(Key=DS4Raw_Gamepad_FaceButton_Top),(Key=DS4Raw_Gamepad_LeftShoulder),(Key=DS4Raw_Gamepad_RightShoulder),(Key=DS4Raw_Gamepad_LeftTrigger),(Key=DS4Raw_Gamepad_RightTrigger),(Key=DS4Raw_Gamepad_Special_Left),(Key=DS4Raw_Gamepad_Special_Right),(Key=DS4Raw_Gamepad_LeftThumbstick),(Key=DS4Raw_Gamepad_RightThumbstick),(bEnabled=False),(bEnabled=False)))
```

Профиль рассчитан на указанные Vendor/Product ID. Для другой модели или режима подключения контроллера проверьте фактическое устройство. В `IMC_Default` используются стандартные `Gamepad_*`, а не внутренние `DS4Raw_*`: преобразование делает viewport-клиент.

В `Config/DefaultGame.ini`:

```ini
[/Script/DronesSetup.ArcadeDrivingSettings]
bEnableArcadeCoasting=True
CoastDecayRate=10.0
StopSpeed=5.0
```

Эти значения влияют и на дистанцию толчка после попадания; правила настройки приведены в разделе 6.

### 3.6. Настройте GameMode, контроллер и локальных игроков

На целевой карте задайте **World Settings → GameMode Override**: `VehicleAdvGameMode` для SportsCar или `OffroadGameMode`. Если сохраняется собственный GameMode, назначьте соответствующие Default Pawn Class и Player Controller Class по перенесённому шаблону.

`VehiclePlayerController` создаёт интерфейс и ввод на **On Possess**, после привязки игрока к автомобилю. При объединении с собственным контроллером сохраните этот порядок и не добавляйте два одинаковых HUD или дублирующие обработчики ввода.

Добавьте PlayerStart на пригодное для автомобиля место. Вторую стартовую позицию рядом создаёт `LocalMultiplayerSubsystem`. На тесной карте адаптируйте спавн в `SetupPlayers`. Исключите другую логику Create Local Player, которая дополнительно создаёт игроков, и Auto Possess Player 0 у всех заранее размещённых машин.

Ввод, владение предметом и прицел должны обращаться к **Self / контроллеру текущего автомобиля**. Не заменяйте их на Get Player Controller 0: это нарушит независимость второго игрока.

Текущая система рассчитана на локальную игру Standalone с двумя игроками. Перенос сам по себе не добавляет сетевую репликацию или поддержку сетевой кооперативной игры.

## 4. Управление и обработчики новых механик

Привязки находятся в актуальном `IMC_Default`; обе новые Input Action имеют **Value Type = Digital (Bool)**.

| Действие | Клавиатура | Xbox | PS |
|---|---|---|---|
| Подобрать ближайший кидательный предмет | F | A | крестик |
| Показывать прицел | Удерживать R | Удерживать X | Удерживать квадрат |
| Бросить | Отпустить R | Отпустить X | Отпустить квадрат |
| Дополнительная кнопка газа | Прежние привязки сохранены | Y | треугольник |
| Дополнительная кнопка тормоза | Прежние привязки сохранены | B | круг |
| Сбросить назначения геймпадов | F2 | — | — |

Дополнительный газ перенесён с X/квадрат на Y/треугольник, тормоз — с A/крестик на B/круг. При объединении IMC проверьте отсутствие прежних конфликтующих привязок. Управление стиком и триггерами сохраняется.

Первое A/крестик назначает геймпад игроку и поглощается кодом присоединения: предмет этим нажатием не подбирается. Следующее нажатие служит подбору. Клавиатура управляет первым локальным игроком. A/крестик для присоединения и F2 заданы отдельно в C++; изменение этих служебных кнопок требует пересборки.

В базовом `VehicleAdvPawn` сохраните:

| Событие | Обработчик | Поведение |
|---|---|---|
| IA_Pickup → Started | TryPickup | Подобрать ближайший подходящий предмет, если руки свободны |
| IA_Throw → Started | BeginThrowAim | Включить прицел, только если предмет подобран |
| IA_Throw → Triggered | UpdateThrowAim | Пересчитывать направление и прицел во время удержания |
| IA_Throw → Completed | ReleaseThrowAim | Убрать прицел и выполнить TryThrow |
| IA_Throw → Canceled | CancelThrowAim | Убрать прицел без броска |

Не заменяйте эту схему одним Started → TryThrow и не добавляйте обязательный Hold-триггер с порогом времени: короткое нажатие должно показать прицел на время нажатия и бросить предмет на отпускании.

Перенос одного IMC без обработчиков, переменных, компонентов и логики базового Blueprint не переносит механику.

## 5. Зависимости предметов, прицела и автомобилей

### 5.1. Подбор, перенос и бросок

Подбираются только `BP_ThrowableCube` и его потомки. Обычные акторы автоматически кидательными не становятся. Для нового предмета создайте дочерний Blueprint, замените `ThrowableMesh` и проверьте физическую коллизию.

`HeldThrowable` хранится отдельно у каждого автомобиля. Во время переноса физика и коллизия предмета выключены, предмет прикреплён справа. После запуска возвращаются физика и коллизия. На прямом участке гравитация выключена; затем включается без обнуления скорости вперёд.

Направление вычисляется **от куба к точке впереди на продольной оси автомобиля** на высоте удержания. Поэтому траектория диагональная. Расстояние до точки на оси берётся из ThrowSpeed × FlightDuration. Собственное вращение куба не влияет на направление. Длина прямого пути куба — 5 м; это не обещание приземления в 5 м от машины.

Во время прямого полёта Object Type предмета временно `WorldDynamic`, после задержки — `PhysicsBody`. Поиск подбора фильтрует PhysicsBody. Не теряйте этот переход: он предотвращает подбор до завершения задержки запуска.

### 5.2. Прицел

В `VehicleAdvPawn` должны сохраниться переменные состояния, граф `Throw Aiming` и компоненты `ThrowAimBeam` / `ThrowAimDot`:

- прицел пересчитывается при движении и повороте автомобиля;
- прогноз состоит из прямого участка и последующего падения с инерцией;
- красная точка появляется на первом блокирующем препятствии; в воздухе отдельной конечной точки нет;
- линия и точка — обычные светящиеся меши с материалом `M_ThrowAimRed`, а не отладочное рисование;
- **Only Owner See** включён у обоих компонентов, коллизия выключена;
- прогноз исключает собственный автомобиль и удерживаемый предмет;
- цель должна блокировать **Visibility**, чтобы появлялся маркер;
- прогноз рассчитан по текущим положениям объектов, не предсказывает будущее движение цели и отскоки после первого контакта.

Текущий радиус прогноза 20 см приблизительно соответствует габаритам тестового куба 40 см. При смене формы/размера предмета адаптируйте прогноз, иначе линия и реальное столкновение могут расходиться.

### 5.3. Усиленный толчок и Hit Events

В `BP_ThrowableCube` граф `Throw Impact Push` обрабатывает **Event Hit**. У `ThrowableMesh` должны быть сохранены:

- корневой Movable-компонент с простой физической коллизией;
- физическая симуляция для свободного предмета, профиль `PhysicsActor` и необходимые блокирующие ответы;
- **Simulation Generates Hit Events**;
- **CCD** для быстрого полёта;
- масса и параметры затухания.

Дополнительный импульс прикладывается к центру основного физического тела кузова по сохранённому направлению запуска, а не по нормали столкновения. Используется Add Impulse с **Vel Change = false**, поэтому масса кузова влияет на результат.

`CanApplyThrowPush` разрешается при Launch и расходуется на первом блокирующем контакте, включая стену или землю. Повторные контакты, отскоки и лежащий куб не дают дополнительного усиления. Pickup сбрасывает состояние; новый Launch разрешает один новый толчок. Собственный автомобиль исключён.

### 5.4. Если используются другие автомобили

Самый простой первый перенос — сохранить SportsCar и OffroadCar как наследников актуального `VehicleAdvPawn`. Для независимого автомобиля целевого проекта недостаточно добавить только кнопки и камеру:

1. Перенесите логику подбора/прицела, её компоненты, переменные и корректное владение либо организуйте наследование от базового Blueprint без потери настроек целевой машины.
2. Текущий граф усиленного толчка делает Cast к `VehicleAdvPawn`. Если цель другого класса, адаптируйте проверку получателя; иначе дополнительного толчка не будет.
3. Текущая реализация работает с корневым `SkeletalMeshComponent`, который содержит физическое тело кузова. Если корень — Scene/Capsule или кузов находится в другом компоненте, измените поиск физического получателя импульса и тела бросившего автомобиля.
4. Для тела кузова используется кость с индексом 0. Проверьте её соответствие реальному физическому телу нового скелета и при необходимости замените выбор.
5. В предмете есть свободные Physics Constraint-компоненты `ThrowOwnerCollisionGuard` и `ThrowWheelGuardFR/FL/BR/BL`. Они исключают только контакты с кузовом и колёсами бросившей машины; все шесть осей свободны и не удерживают предмет. При новом подборе прежние связи разрываются.
6. Для колёс используются имена `Phys_Wheel_FR/FL/BR/BL` у SportsCar и `PhysWheel_FR/FL/BR/BL` у OffroadCar. Для другого Physics Asset измените Bone Name и при необходимости число исключений. Не удаляйте исключения без проверки: при диагональном броске куб может задеть свою машину.
7. Проверьте физическую симуляцию кузова, массу, Visibility и коллизию с предметом. Для нового размера машины также подстройте положение удержания и радиус подбора.

Если отказываетесь от Chaos Vehicles, сплит-скрин и маршрутизацию ввода можно сохранить, но движение, `ArcadeCoastingComponent`, выбор физического тела и применение импульса потребуется адаптировать. Компонент замедления сейчас рассчитан на `ChaosWheeledVehicleMovementComponent` и автоматически добавляется двум начальным автомобилям в `SetupPlayers`.

## 6. Параметры механик и повторная настройка физики

| Параметр | Текущее значение | Где менять |
|---|---|---|
| ThrowSpeed | 1000 см/с | BP_ThrowableCube → Class Defaults |
| FlightDuration | 0,5 с | BP_ThrowableCube → Class Defaults |
| Длина прямого свободного пути | 500 см = 5 м | ThrowSpeed × FlightDuration при Linear Damping = 0 |
| PushImpulse | 3 000 000 кг·см/с | BP_ThrowableCube → Class Defaults → Throwing → Push Impulse |
| Размер тестового куба | 40 см | ThrowableMesh → Scale; базовый меш 100 см, scale 0,4 |
| Масса предмета | 75 кг | ThrowableMesh → Physics → Mass Override |
| Linear / Angular Damping | 0 / 0,5 | ThrowableMesh → Physics |
| Радиус подбора | 400 см | VehicleAdvPawn → Pickup and Throw → Sphere Overlap Actors |
| Смещение удержания | X=0, Y=230, Z=100 см | BP_ThrowableCube → Pickup → Set Actor Relative Location |
| Радиус прогноза | 20 см | Throw Aiming → два Predict Projectile Path By Trace Channel |
| Частота прогноза | 60 | Sim Frequency в обоих узлах прогноза |
| Прогноз после прямого участка | 3 с | Max Sim Time второго узла прогноза |
| Толщина линии / диаметр точки | 1,5 / 8 см | DrawThrowAimPath: Scale Y/Z=0,015; ShowThrowAimHit: Scale=0,08 |
| CoastDecayRate | 10 | Project Settings → Game → Arcade Driving или DefaultGame.ini |
| StopSpeed | 5 см/с | Там же |

После изменения Blueprint нажимайте Compile и Save вне Play. Значения, переопределённые в дочернем Blueprint или экземпляре, проверяйте отдельно: изменение родителя их автоматически не заменит.

В **Project Settings → Game → Arcade Driving**:

- Enable Arcade Coasting включает быстрое гашение качения;
- Coast Decay Rate = 10 — текущая скорость экспоненциального уменьшения горизонтальной скорости; 6–8 дают больше качения, 12–15 — более резкую остановку;
- Stop Speed = 5 см/с — порог обнуления малой остаточной скорости.

Помощь действует при отпущенных газе и тормозе/заднем ходе, когда хотя бы одно колесо касается земли. Она не подаёт тормоз/задний ход, не гасит вертикальную скорость и выключена в воздухе. Разгон, сцепление, подвеска и заносы также определяются Chaos Vehicle.

**Толчок примерно на 2 м — ориентир, а не гарантированная дистанция.** PushImpulse выбран с учётом текущего сильного замедления. В изолированных проверках прибавка скорости составила около 1980–1990 см/с; оценка при одном только экспоненциальном затухании с коэффициентом 10 — около 198–199 см. Полный путь по земле этим тестом не измерялся.

На итог влияют масса и движение машины, газ, тормоз, ручник, шины, трение, поверхность и уклон. После переноса на 5.6 или смены автомобиля подберите PushImpulse заново на ровной площадке, меняя его шагами по 20–25%. Значение 0 отключает только дополнительное усиление: обычное физическое столкновение остаётся. PushImpulse не меняет скорость куба, дальность его полёта и прицел.

## 7. Проверка после переноса

### 7.1. Сборка и ресурсы

1. Перезапустите редактор после изменения модулей и Config.
2. Проверьте загрузку Runtime-модуля. В IMC_Default должны отображаться Stick Half Axis, Dead Zone и Exponent; отсутствие класса означает проблему загрузки/ссылки на модификатор.
3. Выполните Compile/Save всех затронутых Blueprint, проверьте родительские классы, компоненты, материал прицела и отсутствие Missing Class / Accessed None.
4. Проверьте обе исходные карты и целевой уровень, наличие предметов и свободные стартовые позиции.

### 7.2. Два игрока и управление

1. В Play установите Number of Players = 1 и Net Mode = Play Standalone: второго игрока создаёт subsystem.
2. Убедитесь, что появились ровно две половины экрана, два автомобиля, отдельные камеры и HUD.
3. Присоедините геймпады через A/крестик в нужном порядке. Повторите с Xbox первым и PS первым, затем проверьте F2 и повторное назначение.
4. Проверьте газ, тормоз/задний ход, диагональ стика, триггеры, дополнительные кнопки Y/треугольник и B/круг, ручник, камеру и сброс положения.
5. Убедитесь, что подбор не включает тормоз, бросок не включает газ, действия одного игрока не воздействуют на другого.

### 7.3. Подбор, прицел, бросок и толчок

1. Каждый игрок подбирает свой куб. Чужой удерживаемый предмет не подбирается, обычный актор не подбирается, второй предмет при занятых руках не берётся.
2. Машина может ехать и выполнять обычное управление с предметом справа. Предмет не мешает собственной машине.
3. Удержание X/квадрат/R показывает прицел без броска. Линия обновляется при движении и повороте, видна только владельцу.
4. Точка появляется на другом автомобиле, препятствии и земле после участка падения; линия не проходит сквозь первое препятствие. При направлении в воздух отдельной точки нет.
5. Отпускание бросает предмет один раз и убирает прицел. Короткое нажатие тоже бросает на отпускании. Canceled убирает прицел без броска. Без предмета прицел не включается.
6. Предмет летит наискось к точке впереди по оси автомобиля, независимо от поворота куба. Проверяйте оба типа машин: собственные кузов и колёса не должны сбивать траекторию.
7. Без препятствий прямой путь составляет примерно 5 м, затем предмет падает с сохранённой инерцией. Возможна погрешность физического кадра; приземление находится дальше 5 м.
8. Попадание усиливает толчок второго автомобиля по направлению броска. Проверьте оба направления «игрок 1 → игрок 2» и наоборот, оба автомобиля, газ/тормоз/ручник, разные поверхности.
9. Повторный контакт или лежащий куб не даёт повторного усиления. Первый удар о землю/стену расходует усиление; новый подбор и бросок разрешают его снова.
10. Проверьте возврат предмета к подбору после прямого участка и несколько последовательных циклов.

### 7.4. Standalone Game и упаковка

Повторите проверки в отдельном Standalone Game и собранном Development-пакете. Проверка только в окне редактора недостаточна для владения прицелом, загрузки ресурсов и реальных геймпадов.

В Packaging включите нужные карты. Из-за строковых LoadObject-ссылок добавьте `/Game/VehicleTemplate/Input` и `/Game/VehicleTemplate/Blueprints` в **Additional Asset Directories to Cook**, если карта/логика не содержит явных ссылок на эти ресурсы. Убедитесь, что вместе с Blueprint попали зависимости: материал прицела, меши и Physics Assets. Проверьте собранную игру на отсутствие Missing Asset/Class и появление прицела у обоих игроков.

### 7.5. Автоматические проверки и ограничения инструментов

`Scripts/Test-SplitScreen.ps1` можно перенести как основу проверки сплит-скрина. В нём измените имя `.uproject`, при необходимости имена карт; EngineRoot передайте для UE 5.6:

```powershell
# Выполнять из корня целевого проекта после адаптации скрипта.
& './Scripts/Test-SplitScreen.ps1' -EngineRoot 'C:/Program Files/Epic Games/UE_5.6'
```

Скрипт рассчитан на перенесённый VehicleTemplate и ожидаемые им HUD/автомобили. Он использует синтетический ввод, отключает RawInput/XInputDevice только в своём тестовом запуске и не покрывает новые механики полностью. Не переносите эти флаги отключения плагинов в обычный запуск игры.

Если перенесён и собран `DronesSetupEditor`, доступны режимы командлета:

| Режим | Назначение | Важное ограничение |
|---|---|---|
| `Verify` | Подбор, перенос, владение, дальность, инерция и физический толчок | Может сохранять/компилировать Blueprint и корректировать IMC/графы |
| `ConfigureAim` | Подготовка недостающих графов прицела и проверки для обеих машин | Может изменять и сохранять ассеты |
| `ConfigurePush` | Подготовка толчка, сравнение с обычным ударом, однократность | Может изменять и сохранять ассеты; использует эталонные значения в тестах |

Это инструменты создания/настройки, а не гарантированно read-only тесты. Запускайте при закрытом редакторе в резервной копии/отдельной ветке и проверяйте изменения ассетов. Если целевые графы объединены вручную, сначала адаптируйте инструменты к ним: не запускайте код подготовки на изменённых ассетах без анализа.

Пример одного запуска; путь движка, проекта и имя проекта замените своими:

```powershell
$engineRoot = 'C:/Program Files/Epic Games/UE_5.6'
$targetProject = 'D:/Projects/MyGame/MyGame.uproject'
$editorCmd = Join-Path $engineRoot 'Engine/Binaries/Win64/UnrealEditor-Cmd.exe'
& $editorCmd $targetProject -run=BuildThrowables ConfigureAim -unattended -nop4 -NullRHI -nosound -DDC-ForceMemoryCache -ddc=InstalledNoZenLocalFallback
```

Для других запусков замените `ConfigureAim` на `Verify` или `ConfigurePush`. Проверьте код возврата и фактический лог в `Saved/Logs` целевого проекта. Команда приведена как адаптация проверенного запуска UE 5.5.4, не как уже проверенный запуск UE 5.6. Параметры кэша использовались для обхода локальной проблемы DDC; при иной конфигурации кэша целевой среды адаптируйте их.

Не запускайте `-run=BuildThrowables` без режима на существующих ассетах: это создание базовой механики, защищённое проверкой наличия BP_ThrowableCube. `UpgradeFlight` — разовая команда изменения старой механики; для обычного переноса не требуется.

Тесты используют жёстко заданные пути VehicleTemplate, автомобили и эталонные настройки. После смены имён, графов, скорости, длительности или массы адаптируйте ожидания. NullRHI не проверяет визуальное отображение прицела, материалы, видимость по владельцу на реальном экране или физические контроллеры; ручной прогон остаётся обязательным.
